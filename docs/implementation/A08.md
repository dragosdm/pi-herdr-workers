## Changes and compatibility

- `loop/dynamic-ack.ts`: shared ordinary-controller ownership, token/metadata validation, retirement eligibility and acknowledgement checks. Workflow, orchestration and task-backlog controllers are excluded.
- `loop/types.ts`, `loop/loop-reducer.ts`: optional `pendingWakeId`, explicit fire-cap/one-shot retirement provenance, property-presence token clearing and administrative invalidation.
- `loop/store.ts`: UUID admission records the fire and pending token in one snapshot. All acknowledgement statuses reload and check the token under the store lock. Continue owns the iteration increment and clears the token; pause keeps A09's checkpoint merge in that transaction; completion deletes. Administrative resume does not acknowledge an iteration. Legacy normalization derives the specified full SHA-256 identity without inspection writes.
- `loop/index.ts`: ordinary dynamic activation uses atomic admission and emits only after persistence succeeds. Existing owned-controller and cron/event paths remain separate.
- `loop/scheduler.ts`: only retirement cause plumbing changes. Repeated cap retirement and one-shot retirement preserve a legitimate pending token. **A11's awaiting-before-expiry pump ordering is unchanged.**
- `loop/tools/loop-tools.ts`: required bounded `wakeId` schema and direct-call validation, explicit status validation, no implicit resume, full token inspection text and stale-work recovery guidance.
- `loop/runtime/notification-runtime.ts`: messages and queued/delivered details retain the saved identity. Legacy pending messages without tokens request inspection instead of printing an undefined token. Notification delivery keys are unchanged.
- `README.md`: token example, intentional input compatibility break, explicit administrative resume, deterministic legacy recovery, shared-writer upgrade requirement and failure boundaries.
- `tests/extensions/loop-dynamic-ack.test.ts`: dedicated positive regression matrix.
- `tests/extensions/audit-loop-monitor.test.ts`: only the A08 known-gap assertion is inverted. A09 pause and omitted-checkpoint/fire-cap fixtures now admit wakes and supply tokens. Other known-gap assertions, including A11, remain characterizations of unfixed behavior.
- `tests/extensions/loop-pause-checkpoint.test.ts`: required API adaptation only. Seeds admit actual wakes; test wrappers provide those tokens. Second checkpoints/completion after pause now explicitly resume and admit another wake. Token-consumption expectations and audit payloads reflect A08. The schema still checks all original field types; pause still must preserve a timed legacy checkpoint, ignore malformed pause intervals, save empty/Unicode fields, and keep A09's rollback/mirror/recovery assertions. No tests were removed.

`wakeId` is intentionally required for all three statuses. There is no tokenless fallback, inferred production token, or `LoopUpdate` resume path. Old shared-file writers must be upgraded together. Tokens are correlation values, not credentials or proof that old external work remains relevant.

## Concurrency, recovery and failure evidence

The dedicated tests cover stale A during B for all statuses, wrong-loop identities at equal timestamps, never-fired loops, schema and bypassed-schema rejection, invalid intervals, expiry, cap and one-shot retirement, cancellation and explicit resume. Rejections compare complete controller snapshots, trigger registrations, accepted-update audit entries and persistence callbacks.

Two file-store readers test locked reload after another writer consumes the token. Additional stale-preflight cases change expiry, budget or administrative status before acceptance and assert unchanged file bytes and no registrations/audits. Two concurrent child processes open the same temporary file before acknowledgement and start together; exactly one commits. Each child has a ten-second process timeout; temporary files are removed. In-process continue-versus-pause/completion races cover both winning orders.

Admission writes one complete snapshot containing fire count 1 and a UUID. The real extension factory tests both tool-created idle and `/loop` goal activation, asserting saved identity before event emission and matching message details. It also verifies read-only bookkeeping still permits `LoopUpdate` while blocking bash. Notification queue/restore/delivery retains the same token.

Pending snapshot reload retains identity and does not dispatch again. Accepted-state reload rejects replay. Legacy session snapshots and two file readers derive the same migration token; inspection does not rewrite the file. Legacy capped/one-shot pending states remain acknowledgeable, while administrative legacy pauses require resume. Malformed token/awaiting metadata fails closed locally without hiding unrelated controllers and is repaired by explicit pause/resume.

Memory snapshot-append failures roll back admission and all three acknowledgement statuses, leaving the same token retryable and scheduling untouched. A shared-file mirror failure, auxiliary audit failure or post-commit registration failure leaves the authoritative token consumed; a retry rejects. Cancellation-first rejects the acknowledgement; update-first remains committed before subsequent administrative cancellation. These tests do not establish power-loss durability or exactly-once external/model execution.
