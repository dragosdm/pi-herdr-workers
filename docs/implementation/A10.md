## Change and compatibility

The private command router recognizes five cron-shaped fields before dynamic fallback, validates syntax first, then warns if no prompt remains. It uses the existing validator. Incomplete whole-token `event`/`when` forms warn after the unchanged complete-event match fails. Rejection calls only `ui.notify`, never store or trigger accessors.

Valid cron and shorthand retain normalization, notifications and the 25-wake cap. A05's duration-prefix matcher remains unchanged. Complete events preserve source casing and prompt spacing. Prose goals still activate once with a 20-wake cap. Menu cancellation and the headless error remain unchanged. Five-field numeric goals now require preceding prose or explicit idle-tool creation. Partial cron, named fields and aliases retain their prior fallback; a sixth numeric token is still prompt text. Saved cron-looking dynamic goals restore without migration.

No tool API, persistence schema, scheduler, storage or interval-parser code changed. Scheduled rollback and inherited A03/A05 tests are intact.

Changed files:

- `loop/commands/loop-command.ts`: private malformed-event route, five-field missing-prompt handling and actionable warnings.
- `tests/extensions/loop-command-routing.test.ts`: 97 dedicated command-boundary regressions with an in-memory store, persistence recorder, creation/accessor counters, registration/removal spies and activation/widget/UI spies. No running schedulers, real models, panes or disk-backed stores.
