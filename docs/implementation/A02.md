## Live-gate correction and specification adjustment

The supervisor tested `e68bd2d` in disposable Herdr 0.8.0 pane `w8:p2`. The bounded printf executed once and returned to the shell. The exact five-row text read returned zero stdout bytes, and both initial and post-reload MonitorList showed `(no output captured)`. A bounded diagnostic with `--lines 50` returned BEGIN/READY/END markers, so this was a readability failure, not an A01 startup failure.

The supervisor authorized a narrow departure from A02's exact `--lines LINES` argv contract. We now separate physical capture rows from displayed nonblank rows. A single `recent-unwrapped --lines 50 --format text` read supplies the production list; no retry, source fallback, full scrollback, extra CLI call or output persistence was added. This 50-row minimum is the bounded window demonstrated by the actual diagnostic. It is not a guarantee of finding output behind arbitrarily many blank rows. Captures that remain empty still get the truthful empty marker. The 15-second timeout, cancellation, five displayed rows and 100-code-unit limit remain unchanged.

The original exact-five argv assertion and line-count assertions were updated to this approved contract, not removed. Five new regressions cover the actual sanitized marker bytes, markers above synthetic trailing screen blanks, last-five display after wider capture, no retry for output beyond the 50-row window, and explicit internal counts above the minimum.
