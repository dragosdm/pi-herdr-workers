## Design and compatibility

`MailboxDeliveryDisposition = void | "retry"` is an internal callback extension. Retry leaves the existing file untouched and not in flight, continues the current sorted snapshot, and creates no timer. `drainInboxAfterCurrent()` reserves one coalesced scan after the active pass, even following a delivery error. Ordinary watch/poll overlap suppression and synchronous reentry suppression remain intact. Stop and non-interactive checks prevent queued scans from doing work.

The extension grants temporary retention only to a shape-valid `started` / `worker_ready` report matching its parent-created pending run, exact concrete pane, and selected protocol. The separate `awaitingReadinessBinding` flag is set only for fresh startup, not re-adoption or assignment delivery. It closes after relationship persistence and provider observation. The retry uses the unchanged live-peer, run/pane, custom-message, and acceptor gates. Existing failure cleanup removes pending authority; shutdown retains scoped uncertainty and clears it before stopping transport.

No tool/RPC schemas, startup flags, protocols, journal formats, state versions, source identity, terminal rules, or creation serialization changed. Provider start remains unconfirmed. Completion without readiness remains valid. No synthetic readiness, historical backfill, worker termination, startup sleep, rollback, or general unknown-sender exception was added. The pre-existing shell delay was not changed.

The existing RPC service intentionally redacts internal errors to `The worker operation failed.` Failure tests assert that contract and the original scoped uncertainty rather than exposing provider error text. The timeout test injects provider-operation rejection named `provider timeout`; it does not wait for a real 70-second Herdr timeout. Existing adapter tests continue to cover operation error behavior.

Persistence-error testing includes the actual memory-before-error relationship mutation. The spawn still fails. A subsequent report can be injected under that surviving relationship and uncertainty binding, rather than remaining deferred. Journal-failure testing preserves successful spawn after binding while requiring normal acknowledgement for readiness.

Restart tests reopen private test JSONL with an empty receiver queue. Surviving files, custom entries, and accepted journals use normal restoration. The interrupted pre-binding test restores the exact saved storage cut before shutdown, containing registration and endpoint but no relationship or lifecycle journal. It remains registered at sequence zero, rejects the file, and fabricates neither readiness nor uncertainty. This is a controlled storage-boundary test, not a process-kill or power-loss claim.
