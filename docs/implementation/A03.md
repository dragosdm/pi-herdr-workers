## Changed files and boundaries

- `loop/store.ts`: resolve cron/hybrid schedules inside the existing creation/resume lock before reducer mutation. No changes to reducer, snapshot version, or shared persistence infrastructure.
- `loop/scheduler.ts`: clear scheduling maps on start, wrap only next-occurrence computation in `ScheduleResolutionError`, pause each failed schedule, and continue. Quarantine write failures propagate with the controller ID; unrelated storage/programming errors are not relabeled. `pump()` ordering is unchanged.
- `loop/trigger-system.ts`: stop registrations before rebuilding from a fresh post-quarantine list. Failed hybrid event registration removes the timer. Existing stop/start debounce history remains intact.
- `loop/tools/loop-tools.ts`: reject already-aborted creation; capture store/trigger instances; on registration failure attempt both ID-local cleanups, preserve the primary error, and report cleanup failures. Expose pause reasons in `LoopList`.
- `loop/commands/loop-command.ts`: retain cron rollback while attempting both cleanups; guard resume, pause rather than delete an existing controller on registration failure, and display pause provenance. Rendering/activation after successful registration does not trigger rollback.
- `tests/extensions/loop-creation-recovery.test.ts`: dedicated tests use real stores/scheduler/triggers, the shared fake event bus, disposable files, tool/command adapters, and a controlled host running `loop/index.ts`. Fires call the real store or the wired extension's real fire handler. All owned timers/subscriptions are stopped; file fixtures remove only their own temporary directory.
- `tests/extensions/audit-loop-monitor.test.ts`: convert only A03's known-gap assertion to positive expectations; strengthen the existing command regression to compare complete snapshots. Other findings remain unchanged.
- `README.md` and the dated A03 audit note: document paused recovery and correction without rewriting historical observations. This file records implementation evidence.

The input schema, success text, defaults, event inference/filtering, recurring/read-only behavior, cap of 25 controllers, seven-day lifetime, slash defaults of 25 scheduled/event wakes and 20 dynamic wakes remain unchanged. A future occurrence within the current resolver horizon but beyond the lifetime is accepted and arms expiry only. Resolver horizon, day matching, jitter, shorthand rounding and hybrid grammar are not changed. “Unavailable” does not mean every rejected schedule is mathematically impossible.

Only preflight failures promise zero mutation. Late registration failure may consume an ID and append creation/deletion snapshots. Cleanup is by ID, not a whole-store rollback; a second file-store writer's healthy entry survives. Registration stays synchronous with no new await. An abort after registration and an activation callback failure do not silently delete committed work. No transaction across external effects, cross-process exactly-once guarantee, or power-loss guarantee is claimed. Session snapshot visibility follows the existing journal contract. Memory scope remains ephemeral.
