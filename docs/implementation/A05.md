# A05 implementation evidence

## Scope and compatibility

Implemented [A05](../specs/A05.md) on `fix/audit-a05`, stacked on reviewed `fix/audit-a03` at `131912d1ca071dfe156c8bc018b4dc04a3a786a0`. The [spec index](../specs/README.md) controls ordering. Specifications are tracked in PR [#11](https://github.com/dragosdm/pi-herdr-workers/pull/11).

This intentionally tightens input acceptance. Only exact entries in the existing 14-duration table succeed. `60s` still selects `*/1 * * * *`; `5m` still selects `*/5 * * * *`; `0m` now throws a positive-safe-integer error; `2d` and `3m` now throw an unsupported-interval error instead of selecting a shorter cadence. Error input echoes are capped at 120 characters plus an ellipsis. There is no nearest-cadence fallback.

Signed, decimal, exponent, and non-finite unit-suffixed inputs are reserved narrowly for validation instead of accidentally starting event/dynamic controllers. Explicit event intent remains an escape. Explicit five-field cron, including `*/3 * * * *`, remains legal. Dynamic `nextInterval` remains an elapsed-delay API and still accepts `30s`, `3m`, and `2d` within the existing lifetime limit.

Saved schedules and schemas are unchanged. A legacy normalized daily controller cannot reveal whether it originated as `1d` or rounded `2d`; it is neither rewritten nor removed. README directs users to inspect `LoopList` and explicitly cancel/recreate incorrect schedules. A03 preflight, rollback, and isolated recovery remain intact.

## Changed-file rationale

- `loop/loop-parse.ts`: exact lookup, numeric validation, bounded error echoes, pure duration-prefix recognizer, shared timing note. Cron validation/evaluation and jitter algorithms are unchanged.
- `loop/tools/loop-tools.ts`: narrow inference guard, parameter wording, cron/hybrid text and expanded timing explanation. A03 creation transaction and dynamic-update code are unchanged.
- `loop/commands/loop-command.ts`: same prefix guard and scheduled success timing note. Existing full-cron routing, menu cancellation, and rollback are unchanged.
- `tests/extensions/loop-interval-validation.test.ts`: dedicated positive matrix regressions.
- `tests/extensions/audit-loop-monitor.test.ts`: exactly the two owned A05 cases converted to rejection assertions with the specified names. The other 13 cases are unchanged from the A03 parent.
- `README.md`: accepted set, rejected examples, literal event escape, local time/DST/jitter/busy-delivery semantics, dynamic-delay distinction, and legacy schedule limitation.
- `docs/implementation/A05.md`: verification and acceptance evidence.

No dependency, lockfile, store, scheduler, schema, protocol, audit-history, or specification changes. No live experiment was run; A05 explicitly requires none. Other audit characterizations still reproduce findings outside A05. Passing this suite is not a claim that all findings are fixed or that every possible regression has been excluded.
